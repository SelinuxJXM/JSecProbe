# JSecProbe v2.4.10 更新内容

本次是一轮**低风险、不改数据库、不改统计口径**的一致性收口，顺带修掉一个会误导测评结论的显示缺陷：AI 智能辅助把「不符合」的判定结果显示成了「符合」。

## 修复

- **修复：AI 分析结果的「不符合」被显示成「符合」**

  AI 智能辅助面板给结论标签配颜色时，判断顺序写反了：先用「包含『符合』两个字」判为符合，再判部分符合、不符合。而「不符合」「部分符合」这两个词里也都含有「符合」，于是先被命中，标签显示成绿色的「符合」。

  数据库里存的结论并没有错，错的是这一个显示标签；但在现场逐条核对 AI 建议时，看到绿标很容易直接采信，风险不小。现在标签样式与「应用 AI 结果到表格」共用同一个解析函数，写入什么、显示什么，口径完全一致。

## 一致性收口

测评结论的取值此前散落在多处：现场核查页切换安全域、切换资产时各抄了一份「数据库值 → 界面值」映射表；应用 AI 结果（单条 / 批量）各抄了一份「中文结论 → 界面值」映射表；后端校验合法状态又单独列了一份白名单；统计 SQL 里还有一份枚举顺序。任何一处漏改，都会表现为「保存得进去、但统计不对」或「AI 说不符合、表格里是空」这类不报错的静默偏差。

- 新增 `shared/assessment-result.ts` 作为**结论值域的唯一真相源**，集中声明界面值、数据库值（含新旧两套历史格式）、统计分组，以及三个解析函数。
- 上述 4 处映射表与后端白名单全部改为引用同一份定义，删除重复代码约 60 行。
- AI 返回的结论文本改为**否定优先**解析（不符合 > 部分符合 > 不适用 > 符合），并兼容常见英文别名；AI 换一种措辞时不再落成空白结论。

## 质量保障

- 新增 `tests/shared/assessment-result.test.ts`（30 条用例）：覆盖各类新旧格式、脏值、否定优先顺序，断言「写入值」与「显示样式」必须对同一段文本得出同一个结果，并校验后端白名单与共享值域完全一致。
- 加入**反漂移扫描**：测试会读取统计 SQL、报告服务、项目与问题 IPC 中的 `result IN (...)` 字面量以及统计枚举顺序，一旦发现某处偷偷新增了共享值域里没有的结论值即失败，避免下次改动再次分叉。
- 验证：`npm run typecheck` 退出码 0；`npm test` 7 个文件 100 个用例通过、1 个用例按环境跳过，退出码 0。

## 兼容性

数据库结构无变更，**未改动统计 SQL 与 `notapplicable` 历史口径**，已有测评数据不受影响，可直接覆盖升级。

> 说明：本次刻意只做低风险高收益的语义收口，未涉及证据溯源块、审计哈希链、巨型组件拆分等结构性改造。
