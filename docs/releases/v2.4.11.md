# JSecProbe v2.4.11 更新内容

本次以**修复数据丢失**为主：AI 分析回填的测评结论此前从未真正写进数据库，切换页面就会消失。同时修掉一个反复刷屏的控制台报错，并让 AI 功能在等待云端模型时的反馈更及时。全程不改数据库结构、不改统计口径。

## 重点修复：AI 分析结果回填后切页丢失

**现象**：在现场核查页做 AI 批量分析（或单条分析后点「应用结果」），表格里看起来已经填好了结论与说明，但只要切换页面、切换测评对象再切回来，回填的内容全部消失。

**原因**：自动保存采用的是「脏行快照」——只有被登记为「有改动」的行才会发往数据库。AI 回填时直接修改了内存里的表格行对象，却**没有登记改动**，于是保存动作看到「没有待保存内容」就直接返回，一次数据库写入都没发生。界面上的数据是纯内存假象，切页时整表从数据库重建，自然全没了。

批量分支还把保存结果直接丢掉，所以连失败提示都没有，反而弹出「已自动填入 N 条测评记录」。另外单条分析里有一条「直接写库兜底」的备用路径，但它漏传了后端强制校验的 `projectId` 以及资产、方法、证据路径等字段，一直被拒绝——**两条回填路径其实一次库都没写进去过**。

**现在的做法**：

- 新增 `saveAppliedRows()`：把本次改动的行统一标脏 → **立即同步落库**（不再等 1.5 秒防抖）→ 以脏标记确认并发补跑的结果。
- 单条分析传 `[该行]`、批量分析传去重后的全部改动行；原先那个字段不全的旁路删除，全部走自动保存通道，保证写入口径与手工编辑完全一致。
- 保存成功 / 失败分别给出明确提示；**失败时保留脏标记**，切页前的 flush 会先重试，仍失败则阻断切换并提示，不会再静默丢数据。

> 提醒：v2.4.10 及更早版本里已经因切页丢失的那批回填内容无法找回——它们从未进入数据库，需要重新跑一次 AI 分析或手工补填。

## 修复：操作窗口时控制台反复报 `guid` 错误

老用户（引导已完成或跳过）拖动窗口、最大化 / 还原、开合 DevTools 时，控制台会反复抛出 `Cannot read properties of undefined (reading 'guid')`，并伴随 `ResizeObserver loop completed with undelivered notifications`。

这里的 `guid` 不是 Windows 的 GUID，而是新手引导步骤的**高亮锚点名**（`data-guide`）。引导未播放时步骤数组为空，但窗口尺寸变化监听仍无条件去计算高亮位置，读到了空步骤；滚动重算本来就有「引导可见才执行」的保护，唯独 resize 这条漏了。现在两者对齐，并对空步骤做了防御，异常不会再发生。

`ResizeObserver loop...` 则是 Chromium 的一条良性警告，来自界面组件库内部，被应用的全局异常捕获器误当成错误打印，与上面的报错没有因果关系，只是都被尺寸变化触发。现在捕获器会过滤这类警告，避免把真正有用的错误日志淹没。

两类报错都只污染控制台，不会白屏、不会丢数据，也不影响正常引导流程。

## 优化：AI 功能的交互反馈

需要先说明：一次 AI 分析常见的 **30–60 秒总耗时在云端模型本身**（多模型故障转移 + 动态超时），这一轮**没有、也无法靠前端把等待变短**；优化的是「点了没反应、进度不动、进度倒退」这类跟手感问题。

| 功能 | 原来 | 现在 |
| --- | --- | --- |
| 单条分析 | 点击后先等读取配置，才弹出窗口 | 校验完立刻弹窗并亮起加载状态 |
| 批量分析前置准备 | 读配置、提取文档、读文本期间一直显示静止的「准备中...」 | 分阶段实时更新：读取配置 → 提取 N 个文档 (i/n) → 提交 N 项 / M 张图 |
| 等待模型返回 | 每 2 秒 +1%，到 90% 后彻底静止，文案还写「正在提交」 | 每秒报活，显示「AI 正在分析中，已等待 N 秒」，阶段正确点亮进度弹窗第 4 步 |
| 进度轮询 | 2 秒一次，旧状态会盖掉刚推送的新状态 → 进度条倒退闪烁 | 1 秒兜底且只补不退；完成后关闭弹窗的延迟由 800ms 缩到 400ms |
| 问题清单·AI 分析问题描述 | 假进度自动走到「正在生成问题描述」，但请求还在云端 | 停在「等待响应」并显示已等待秒数，与同类组件对齐 |

未纳入本轮的（需改主进程请求链路，风险较高）：流式输出 / SSE、调整多模型故障转移策略与动态超时、AI 助手对话改流式。

## 质量保障

- 新增 `tests/renderer/ai-result-save.test.ts`（7 条用例）：覆盖标脏落库、空改动、并发补跑、失败保留脏标记，以及单条 / 批量两条路径的传参与失败提示。
- 更新结论值域反漂移断言：唯一允许存在的「界面值 → 数据库值」映射在自动保存模块，AI 侧不得再起旁路。
- 验证：`npm run typecheck` 退出码 0；`npm test` 8 个文件 107 个用例通过、1 个按环境跳过，退出码 0；版本号一致性检查通过。

## 兼容性

数据库结构无变更，已有测评数据不受影响，可直接覆盖升级。本次只改前端交互与显示层，以及主进程的进度上报文案，未改动 AI 请求、超时与并发逻辑。
