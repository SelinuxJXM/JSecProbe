# JSecProbe v2.5.0 更新内容

本次是一个**体验大版本**：AI 助手对话改为流式输出（边生成边显示），多模型切换不再为一个反复失败的模型干等，现场核查的单行 AI 分析从「点了之后界面完全不动」变成每秒有真实反馈。全程不改数据库结构、不改测评结论口径、不改已有数据。

## 新增：AI 助手对话流式输出

过去点发送后要等整段回答生成完才一次性出现，等待期间只能看着加载圈。现在文字按模型返回的节奏逐段追加显示，首字出现的时间明显提前，长回答不再像「卡住」。

实现上复用了主进程现有的网络栈（`session.fetch`），新增 `shared/ai-stream.ts` 统一解析 SSE、NDJSON 与一次性 JSON 三种返回格式，兼容本地 Ollama / OpenAI 兼容端点 / 各类中转站；跨数据包的半行拼接、`data:` 前缀、`[DONE]`、注释心跳都做了处理。

几个边界情况一并处理：

- **首块前失败才回退**：若端点不支持流式、返回非 2xx、或 20 秒没等到第一个字，自动退回原来的一次性请求，用户不会卡死；一旦已经开始吐字就不再换模型重发，避免两段内容拼接与重复计费。
- **半截回答保留**：中途断流时已生成的文字不丢弃，标注「生成中断」，由用户决定是否重试。
- **主动停止**：点停止后保留已经生成的内容，不回滚、不清空。

> 流式只改变「什么时候能看到字」，**不改变一次回答的总耗时**。需要完整 JSON 才能解析回填的功能（单行分析、批量截图分析、报告生成等）仍走一次性请求，界面上不会显示 JSON 碎片。

## 优化：失败模型短时降权与探活

云端配了多个模型时，原来按顺序串行重试：排在最前的模型如果一直超时，每次请求都要先白等一整轮超时才轮到下一个，体感特别慢。

现在主进程维护一份内存健康记录：某模型连续失败后进入 5 分钟冷却，排序时排到健康模型后面（**不剔除**，冷却结束仍会再试）；冷却中的模型本次只给 15 秒探活；一旦成功立即清除记录。用户主动取消、API Key 缺失、地址填错这类与模型本身无关的失败不会被记为模型故障。

`ai:chat` 与 `ai:chatStream` 共用同一套健康排序，口径不会分叉。

## 优化：单行 AI 分析等待期不再「界面死了」

现场核查页点单条 AI 分析后，从提交到模型返回这段时间此前**没有任何进度上报**：6 步流程条永远停在第 2 步「AI正在识别内容...」，文案一动不动，而动态超时可能长达几分钟；3→4→5→6 步全在结果回来那一瞬间闪过，用户很容易以为程序卡住而重复点击。

现在把批量截图分析里已验证过的等待报活抽成公共模块 `shared/ai-wait-progress.ts`，单行分析接入后：

- 每秒推送一次**真实经过的秒数**（「AI正在分析关键证据点，已等待 Ns...」），不推测模型生成了多少内容；
- 进度条从 33% 缓慢推进到 88%，只增不退且封顶，不会出现「进度条走满却没结果」；
- 结果返回后由原有流程条接管到 100%，步骤显示逻辑不变。

批量截图分析改用同一个公共模块，行为与之前逐字节一致。单条与批量共用进度通道，新增 `scope` 区分，并让批量弹窗与页面常驻订阅都过滤掉单条事件，避免并发时进度串台。

整改建议、问题描述的单条等待原本就有真实秒数，批量截图分析原本就有心跳，本轮未重复改动。

## 兼容性

数据库结构无变更，已有测评数据、项目与证据文件不受影响，可直接覆盖升级。AI 配置无需重填；流式在本地引擎或中转站不支持时会自动退回原有一次性请求。
