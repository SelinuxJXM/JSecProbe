# JSecProbe v2.5.1 更新内容

本次是一个**小版本修复**，处理现场核查「导出 Excel」的范围过滤问题：只勾选一个资产时，导出的文件里不该再夹带其他全局层面的工作表。不改数据库结构、不改测评结论口径、不改已有数据。

## 修复：只选 1 个资产，却导出一堆「全局层面」sheet

有用户反馈：在导出弹窗里只勾了 1 个「运维终端」，导出的 Excel 却还带着好几张「XX_全局层面」工作表。

排查后确认不是数据串了，而是后端把**「一个全局层面都没勾」误判成了「全部全局层面都要」**。前端会把勾选拆成两组参数：`assetIds=[运维终端]`、`domainIds=[]`（空数组表示全局层面一个都没选）。后端 `assessment:exportExcelByAssets` 原来的判断是：

```ts
const hasGlobalData = !domainIds || domainIds.length === 0 || domainIds.includes(domainKey);
```

中间的 `domainIds.length === 0` 一旦命中，每个层面域都会被当成「需要导出」，于是只要该域有测评项就会生成一张全局层面工作表。

**这些多出来的表不是空壳**：它们装的是 `globalRecordMap`（`assetId` 为空的全局测评记录），等于把没勾选的全局结论与证据引用也一并写进了文件。如果只想把某个终端的结果交给外包或甲方，这点比「表多了」更值得注意。这个兜底推测是为兼容早期「不传第三参 = 导出全部」的调用方式，但现在全项目只有一处调用，且弹窗已明确区分勾选与未勾选，兜底就和显式空数组撞车了。

现在把判定抽成可单测的纯函数 `shared/export-scope.ts` 的 `shouldIncludeGlobalSheet()`：**只有参数真的没传**（`null` / `undefined`，保留旧调用兼容）才按全量处理；显式传 `[]` 严格表示一个全局层面都不导出。修完后的行为：

| 勾选情况 | 导出结果 |
|---|---|
| 只选 1 个资产 | 只有 1 张该资产的工作表 |
| 只选某几个全局层面 | 只出这几个的 `_全局层面` |
| 全选 | 全部全局层面 + 全部资产（与原来一致） |
| 混合勾选 | 内容不变，文件名改为「混合内容_现场核查记录」 |

## 顺手修掉一处死代码

`contentLabel`（导出默认文件名）里「混合内容」的分支写在末尾，永远被前面的 `domainIds` 分支抢先命中，导致同时勾了全局层面和资产时，文件名显示成「XX_全局层面」，看着像只导了全局层面。现把混合分支提到最前，文件名与实际内容一致。

## 质量保障

- 新增 `tests/shared/export-scope.test.ts` 共 8 条用例：未传 / `null` 视为全量、显式空数组不导出、按 `domainKey` 精确匹配、全选场景；另加 3 条源码反漂移门禁（IPC 必须调用纯函数、禁止再出现 `domainIds.length === 0`）。
- 验证：`npm run typecheck` 退出码 0；`npm test` 12 个文件 152 个用例通过、1 个按环境跳过，退出码 0；版本号一致性检查通过。

## 兼容性

数据库结构无变更，已有测评数据、项目与证据文件不受影响，可直接覆盖升级。仅调整 sheet 生成范围与默认文件名，不碰 `JSON.parse`、不碰任何数据库写入；导入侧按文件里**实际存在的**工作表处理，缺全局层面表只会少导入、不会删除已有记录，所以导出后再导回也不会丢数据。
