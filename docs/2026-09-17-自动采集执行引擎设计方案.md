## 1. 背景与目标

### 1.1 背景

项目内置 319 条等保核查命令（含 Linux / Windows / MySQL / Oracle / PostgreSQL / SQL Server / Redis / WebLogic 等目标类型），当前这些命令仅作为**知识库**使用：测评员在现场核查时手动打开命令库查看/复制界面、复制命令、自行登录目标设备执行、再手动把结果录入测评记录。整个流程依赖人工，效率低且易出错。

### 1.2 目标

实现"**点击按钮自动采集**"：

- 从应用内直接建立到目标设备的连接（SSH / WinRM / 数据库协议 / HTTP）
- 自动执行勾选的核查命令，实时展示进度
- 解析命令输出，经测评员确认后**一键回填**到测评记录
- 全程凭据加密存储、操作可审计、可取消、可追溯

### 1.3 决策摘要

> 完整决策记录与上下文见第 13 节。以下仅列最终结论。

| # | 决策点 | 最终结论 |
|---|--------|----------|
| 1 | 回填方式 | **人工确认制**：采集结果由测评员逐条确认后回填，不自动写入结论 |
| 2 | Windows 通道 | **OpenSSH 优先**，WinRM 作为备选（仅当目标未启用 OpenSSH 时） |
| 3 | Oracle 连接 | **oracledb 7.x thin 模式**，纯 JS，免 Oracle Instant Client |
| 4 | 中间件范围 | **两者都做**：配置命令核查（经宿主 OS）+ WebLogic 控制台 HTTP 探测 |
| 5 | 实施计划 | **已实施完成**：Phase 1-4 + 健壮性 + 多资产并发落地；Phase 5 按需求跳过 |

### 1.4 非目标（本期不做）

- 不做自动判定"符合/不符合"的权威结论（仅提供解析结果与建议，最终由测评员确认）
- 不做远程文件下载/上传、不做 Agent 安装
- 不做批量多项目调度

## 4. 数据模型设计

新增采集相关表 + 复用现有字段，通过 `ensureCollectionTables()` 自动建表（迁移文件仅到 0003，无 `0004` 迁移）；`asset_connections` 表已建但未写入数据（见 4.2）。

### 4.1 `connection_profiles`（连接配置表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | text PK | UUID |
| `name` | text NOT NULL | 配置名称（如"XX 机房核心交换机"） |
| `conn_type` | text NOT NULL | `ssh` / `winrm` / `mysql` / `oracle` / `postgresql` / `sqlserver` / `redis` / `http` |
| `host` | text NOT NULL | 目标地址 |
| `port` | integer | 端口（SSH 默认 22，MySQL 3306 等） |
| `username` | text | 登录用户 |
| `auth_method` | text | `password` / `private_key` / `integrated` |
| `password_encrypted` | text | **safeStorage 加密后密文**，明文不落库 |
| `private_key_path` | text | 私钥文件路径（不存内容） |
| `timeout_ms` | integer | 连接超时，默认 10000；单命令超时独立配置（默认 15s，见 6.2） |
| `extra_config` | text | JSON 扩展（TLS 开关、数据库名、SID、WinRM HTTPS 等） |
| `created_at` / `updated_at` | text | 时间戳 |

### 4.2 资产关联（实施简化：`asset_connections` 表已建但未写入数据）

`asset_connections` 表在 `electron/db/schema.ts` 中已定义（注释为"Phase 1 暂不写入，预留"），但实际业务数据未写入该表。改为在 `connection_profiles` 上直接增加 `asset_id` 字段实现资产一对一关联：

| 字段 | 类型 | 说明 |
|------|------|------|
| `asset_id` | text（可空） | 关联 `assets.id`，一个连接配置对应一个资产 |

- 连接配置与资产**一对一直接绑定**，采集任务通过 `connection_id` 唯一确定目标资产
- 多资产并发 = 为每个资产建立独立连接配置并批量发起采集任务，由调度器并发执行

### 4.3 `collection_tasks`（采集任务表）

| 字段 | 说明 |
|------|------|
| `id` | UUID PK |
| `project_id` | 关联项目 |
| `asset_id` | 关联资产 |
| `connection_id` | 关联连接配置 |
| status | `pending` / `running` / `success` / `partial` / `failed` / `canceled` / `canceling`（执行中取消的中间态） |
| `total_commands` | 计划命令数 |
| `completed_commands` | 已完成命令数 |
| `progress` | 0~100 |
| `started_at` / `finished_at` | 起止时间 |
| `created_by` | 发起用户 |

### 4.4 `collection_results`（采集结果表）

| 字段 | 说明 |
|------|------|
| `id` | UUID PK |
| `task_id` | 关联任务 |
| `command_id` | 关联命令库 id（允许空=自定义命令） |
| `command` | 实际执行命令快照 |
| `status` | `success` / `failed`（退出码非 0）/ `timeout`（执行超时）/ `error`（异常，如连接断开、命令注入被拒） |
| `exit_code` | 退出码 |
| `stdout` | 标准输出 |
| `stderr` | 错误输出 |
| `duration_ms` | 单命令耗时 |
| `parsed_data` | JSON 解析结果 |
| `created_at` | 时间戳 |

### 4.5 `collection_documents`（采集文档元数据表）

保存采集任务生成的 Markdown 报告文件元数据，支持"已保存文档"列表查看、打开所在目录、删除记录。

| 字段 | 说明 |
|------|------|
| `id` | UUID PK |
| `task_id` | 关联采集任务 |
| `project_id` | 关联项目 |
| `asset_id` | 关联资产（可空） |
| `asset_name` | 资产名称（快照） |
| `host` | 目标地址（快照） |
| `file_path` | Markdown 文件绝对路径 |
| `title` | 文档标题 |
| `created_at` | 时间戳 |

### 4.6 回填目标（复用现有字段）

- `assessment_records.command_output` ← 采集 `stdout` / 解析摘要
- `assessment_records.result` ← 测评员确认后的符合性结论
- `assessment_records.evidence` ← 采集结果文本（可选）

## 5. 连接适配器层

### 5.1 统一接口

```ts
interface IConnector {
  connect(profile: ConnectionProfile): Promise<void>;
  execute(cmd: string): Promise<ExecResult>; // { stdout, stderr, exitCode, durationMs }
  disconnect(): Promise<void>;
  testConnection(profile: ConnectionProfile): Promise<boolean>; // 预检，失败返回 false
}
```

`ConnectorFactory` 根据 `profile.conn_type` 返回对应适配器，调度器不感知协议差异；新增协议只需新增一个适配器类。

### 5.2 适配器清单（按已确认决策）

| 适配器 | npm 依赖 | 认证方式 | 说明 |
|--------|----------|----------|------|
| **Linux SSH** | `ssh2` | 密码 / 私钥 | 逐条执行命令，捕获 stdout/stderr；**单命令超时 15s（可配置）** |
| **Windows SSH（优先）** | `ssh2` | 密码 / 私钥 | 复用同一适配器，Windows 优先走 OpenSSH Server |
| **Windows WinRM（备选）** | `winrm-client` | Basic / NTLM，HTTP/HTTPS | **纯 JS（fast-xml-parser + js-md4），自带 TS 类型**，替代原设计自研 SOAP；支持 PowerShell 模式 |
| **MySQL** | `mysql2/promise` | 用户密码 | 执行 `SHOW VARIABLES` / `SELECT` 等 SQL，结果表格化输出 |
| **Oracle** | `oracledb`（7.x） | 用户密码 | **thin 模式纯 JS，免 Oracle Instant Client**，无需运行时客户端检测；`SELECT 1 FROM DUAL` 预检 |
| **PostgreSQL** | `pg` | 用户密码 | 执行核查 SQL；**支持多语句 `;` 拆分逐条执行** |
| **SQL Server** | `mssql` | 用户密码 | 纯 JS（tedious），无本机依赖；支持实例名/数据库名 |
| **Redis** | `ioredis` | 密码 / ACL | 执行 `CONFIG GET` / `ACL LIST` / `INFO`，**多命令按行拆分** |
| **中间件（配置命令）** | 复用 SSH/WinRM | — | Nginx / Apache / Tomcat / WebLogic 配置核查命令经宿主 OS 执行 |
| **WebLogic 控制台（HTTP）** | Node 内置 `fetch` | 控制台账号（可选） | 探测 `/weblogic/ready`、`/console/login/LoginForm.jsp` 等，自动识别版本/会话 Cookie/登录表单特征 |

**通用能力（DB 适配器共用 `db.util.ts`）**：
- **只读校验（注入防护）**：仅放行 `SELECT` / `SHOW` / `WITH` / 只读 `EXEC`，拦截 `INSERT / UPDATE / DELETE / DROP / GRANT / INTO OUTFILE` 等写操作
- **多语句拆分**：正确处理字符串内分号，避免误拆
- **结果表格化**：查询结果输出为对齐文本表格，与 SSH 模式一致
- **单命令超时 15s**（可配置），超时抛 `CommandTimeoutError`，由调度器标记为 `timeout`

## 6. 采集调度器（CollectionService）

### 6.1 任务流程

1. 前端发起 `{ assetId, connectionId, commandIds[] }`
2. 创建 `collection_tasks` 记录（status=pending）
3. `testConnection()` 预检（失败则任务 failed，不浪费命令执行）
4. 连接建立后逐条执行命令
5. 每条命令执行完写入 `collection_results`，更新任务进度，推送进度事件
6. 全部完成 → status = success（部分失败则 partial）

### 6.2 关键策略

| 项 | 策略 | 状态 |
|----|------|------|
| 单资产命令执行 | **串行**（保持输出顺序与数据库核查上下文） | ✅ 已实现 |
| 多资产并发 | 可配置，默认 `maxConcurrent = 3`，环境变量 `COLLECTION_MAX_CONCURRENT` 可调 | ✅ 已实现 |
| 连接超时 | 10s（可配置） | ✅ 已实现 |
| 单命令超时 | 15s（可配置），超时标记 timeout 并继续下一条 | ✅ 已实现 |
| 连接失败重试 | 1 次 | ✅ 已实现 |
| 取消机制 | `status = canceling`，调度器停止后续命令并关闭连接；**排队中任务直接取消为 `canceled`** | ✅ 已实现 |

### 6.3 进度推送

复用现有 `ai:progress` 模式：

- 主进程：`webContents.send('collection:progress', { taskId, stage, message, percent })`
- preload：暴露 `onProgress(callback)`

### 6.4 资源释放

`finally` 中保证 `disconnect()`；任务取消/异常时统一清理连接池，防止泄漏。

## 7. 结果解析与回填

### 7.1 解析器（parsers/）

| 解析器 | 适用场景 | 示例 |
|--------|----------|------|
| `RawTextParser` | 文本输出直接入库 | `cat /etc/ssh/sshd_config` |
| `KeyValueParser` | `key: value` 输出 | `show variables like 'port'` |
| `SqlTableParser` | SQL 查询表格 | `select user,host from mysql.user` |
| `RegexExtractParser` | 提取关键字段 | 从 `/etc/passwd` 提取 UID=0 账户 |
| `RedisInfoParser` | Redis `INFO` 分段 | `# Server` / `# Clients` |

每个命令可配置解析器（默认 `RawTextParser`），解析结果存入 `collection_results.parsed_data`。

> ✅ **已实现**：全部解析器已落地，解析结果以 JSON 存入 `parsed_data`，前端"采集结果"展开区可直接查看。

### 7.2 回填流程（✅ 已确认：人工确认制）

1. 采集完成后前端展示每条命令的 `stdout` 与解析结果
2. **测评员逐条确认"符合 / 不符合 / 部分符合 / 不适用"**（解析结果可预填建议，供参考）
3. 点击"回填到测评记录" → 写入对应资产的 `assessment_records`：
   - `command_output` = 采集输出
   - `result` = 确认结论
   - `evidence` = 解析摘要
4. 回填动作写入操作日志（`operation_logs`），可审计

> 已确认采用**人工确认制**，采集结果不会自动写入测评结论；AI 自动判定建议（Phase 5）已按需求决定不做，未来如需可复用 `ai:analyzeAssessment` 通道扩展，仍由人确认。

| 左栏（连接配置） | **多选连接列表**：每条配置显示复选框 + 名称 + 连接类型 + 主机端口 + 用户；支持**全选/半选**；每条显示**多任务并发状态徽章**（执行中 N / 排队 N），有活跃任务的连接左侧橙色粗边框指示；顶部工具栏提供**批量删除**（选中 N 个）；也支持切换到「新建连接」模式（类型/主机/端口/凭据/数据库名/HTTPS 等），提供「测试连接」；类型切换自动切换默认端口 |
| 右栏（采集设置） | 命令搜索 + **OS 筛选**（自动/全部/指定）+ 已选计数 + 全选/清空；命令列表自适应高度 |
| 底部（执行面板） | Tabs：执行进度（多任务卡片）/ 采集结果 / 已保存文档（见 4.6）；底部显示"已选 N 个连接"与「开始采集（N × M）」按钮 |

**左侧边栏交互细节（v1.3 新增）：**

- **多选机制**：`selectedProfileIds: string[]` 数组维护所有勾选的配置 ID；单击行或复选框切换选中
- **全选复选框**：顶部提供全选 checkbox，具备 checked / unchecked / indeterminate（半选）三种状态
- **并发状态视觉关联**：每个采集任务对象新增 `profileId` 字段，左侧连接列表根据该字段聚合统计活跃任务数并显示徽章（`执行中 N` 橙色 / `排队 N` 蓝色）
- **批量删除**：选中 ≥1 个后顶部出现「删除选中（N）」按钮 → 确认弹窗 → 调用 `collection:batchDeleteProfiles` IPC（事务批量删除）→ 刷新列表并清理无效选中
- **单选兼容**：当仅选中 1 个时自动同步 `currentProfileId`，保持与测试连接、删除当前等单选操作的向后兼容
- **选中态持久化**：`loadProfiles()` 时自动清理已被删除的配置 ID，防止悬空选中

### 9.3 采集进度视图（✅ 已实现：多任务卡片）

## 12. 风险与对策

| 风险 | 影响 | 对策（实际） |
|------|------|------|
| `oracledb` 依赖 Oracle Instant Client，目标机未安装 | Phase 4 功能不可用 | ✅ **已规避**：采用 oracledb 7.x thin 模式，纯 JS 免客户端，无需本机依赖 |
| Node 生态 WinRM 库质量参差 | Phase 3 不稳定 | ✅ **已规避**：选用 `winrm-client`（纯 JS、自带 TS 类型、活跃维护）；OpenSSH 仍为优先通道 |
| `safeStorage` 在 Linux 无 keyring 时不可用 | 凭据无法加密 | ✅ 降级为机器级密钥文件 + 提示风险 |
| 目标设备不可达 / 防火墙拦截 | 采集失败 | ✅ `testConnection` 预检；超时兜底；失败不中断任务；连接失败重试 1 次 |
| 大量命令长时间执行 | 体验差 | ✅ 并发上限（默认 3）+ 单命令超时（15s）+ 可取消（排队中直接取消） |
| 密码明文泄漏 | 严重 | ✅ safeStorage 加密 + 日志脱敏 + 备份处理 + 审计 |
| 采集结果误判 | 报告错误 | ✅ **人工确认制**；AI 建议不做（Phase 5 跳过） |
| 注入攻击（写操作 SQL / 破坏性命令） | 严重 | ✅ DB 连接器只读白名单校验，拦截写操作 |
